# ID-11: catalog UUID primary key — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Promote `Game.uuid` and `Platform.uuid` to be the primary keys, drop the
legacy integer identities, and convert `games_purchase_games.game_id` to `uuid_v7`.

**Architecture:** One migration whose operation order is forced by PostgreSQL
dependencies, using a `db_constraint` detach/reattach around the promotion so the
redundant unique index can drop. Everything that types a catalog id as `int`
moves with it, in one atomic cutover; work that is correct under *both* identities
is pulled ahead of the cutover so the suite stays green for as long as possible.

**Tech Stack:** Django 6, PostgreSQL 18, django-ninja, pydantic, pytest/pytest-django,
TypeScript codegen.

**Design spec:** `docs/superpowers/specs/2026-08-19-issue-646-catalog-uuid-primary-key-design.md`.
Read it before starting. It carries the reasoning; this plan carries the sequence.
The wave plan's checklist (`2026-08-17-uuid-identity-cutover-wave-plan.md`) carries
the recurring seams.

**On this plan's shape:** it names files, interfaces, test cases and the traps, and
deliberately does *not* transcribe the implementation as prose. Each step's notes
exist because that step has a way of passing while proving nothing, or of failing in
a way whose cause is not local. Read the note before writing the code.

## Global Constraints

- **`make check` is the gate**, never a subset, and it includes `e2e/`. Iterate on
  `make check-fast`. Everything runs through `make`; never wrap in `direnv exec .`.
- **Rebase onto `origin/main` before starting.**
- **`sqlmigrate` cannot verify this migration.** It introspects the un-migrated
  database, so it reports the doomed unique-constraint drop as clean. Only a real
  `make migrate` against a real database proves the shape.
- **Never write to `GeneratedField`s** (`duration_calculated`, `duration_total`,
  `price_per_game`, `days_to_finish`).
- **Comments explain intent, not history** — no issue or PR references in code
  comments.
- **Complete words in identifiers**, per `CLAUDE.md`.
- Migration numbering continues from `0012_purchase_related_game_uuid`.

suite stays green. Doing it first shrinks the cutover commit.

- [ ] **Step 1: Write the failing tests.** In `tests/test_filters.py`, add:

## Task 2: The anonymizer's generic identity writer

Still pre-cutover, still green: the writer resolves the identity field by name, and
today that name is `uuid` for every model.

**Files:**
- Modify: `games/management/commands/anonymize_sample.py` —
  `_resequence_identity`, `_remap_referrers`
- Test: `tests/test_anonymize_sample.py`

**Interfaces produced:**
- A module-level helper resolving a model's identity field name (`"id"` when the pk
  is a `UUIDv7Field`, else `"uuid"`), used by both methods.

**Gotchas, all load-bearing:**
- `bulk_update` **refuses** primary-key fields (`ValueError`). A queryset
  `.update(<identity>=…)` does write one. Use the latter for both cases so there is
  one path, not a branch.
- `_remap_referrers` walks `_meta.get_fields(include_hidden=True)`, never
  `related_objects` — the latter drops `related_name="+"` relations, of which
  `UserLibraryPreferences.default_device` is one.
- `_remap_referrers` currently skips `many_to_many` outright. It must walk the
  `Purchase.games` through table, because `_anonymize` rebuilds those rows *before*
  `_reassign_uuids` runs. **The deferred FK never catches this** — the command's
  transaction is deliberately rolled back, so nothing is ever checked.
- A regression test must run **inside** the command's transaction. `_write_fixture`
  is called after `transaction.set_rollback(True)`; a test hooked there measures an
  already-undone database and passes against the bug.

- [ ] **Step 1: Write the failing test.** `test_through_rows_follow_resequenced_game_identities`
  — hook a callback invoked inside the transaction (the same seam the existing
  in-transaction tests use), and assert every `Purchase.games.through` row's
  `game_id` matches a live `Game` identity. Confirm it fails today by
  temporarily asserting against the through table after `_reassign_uuids`.

- [ ] **Step 2: Run it, confirm it fails.**
  `make test ARGS="tests/test_anonymize_sample.py -k through_rows -x"`

- [ ] **Step 3: Implement** the identity-name helper, switch `_resequence_identity`

- [ ] **Step 4: Confirm determinism is intact.** `make test ARGS="tests/test_anonymize_sample.py"`

## Task 3: The cutover

**The suite is red inside this task and green at the end.** There is no window where
both identities exist, so this is one commit. Work in the listed order.

**Files:** the migration, `games/models.py`, `games/urls.py`, `games/filters.py`,
`games/api.py`, `games/signals.py`, `games/views/{game,api-adjacent}.py`,
`games/forms.py`, `common/components/{custom_elements,search_select}.py`,
`games/identity_audit.py`, `games/management/commands/{load_sample_data,anonymize_sample}.py`,
`games/fixtures/sample.yaml.gz`, `tests/test_purchase_fk_uuid.py`,
`tests/{test_deletion_helper,test_returns}.py`.

- [ ] **Step 1: Write the migration test first**, in a new
  `tests/test_catalog_uuid_primary_key.py`, following the harness shape of
  `tests/test_platform_fk_uuid.py` (a fixture migrating down to `0012`, flushing,
  yielding the historic `apps`, and restoring leaf nodes on teardown). Cases:
  - `test_forward_migration_promotes_both_catalog_identities` — seed games,
    platforms, purchases with M2M links, sessions; migrate; assert both pks are the
    former uuid values and **every through link is preserved by identity**, not just
    by count.
  - `test_forward_migration_repoints_every_catalog_foreign_key` — introspect
    `pg_constraint` and assert all seven reference `games_game(id)` /
    `games_platform(id)`.
  - `test_forward_migration_retires_the_redundant_unique_index` — assert no
    non-primary unique index remains on `games_game(id)`.
  - `test_reverse_migration_restores_an_empty_schema` and
    `test_reverse_migration_refuses_a_populated_database` (assert the raise names
    a restore-from-backup).

- [ ] **Step 2: Write the migration.** Operations, in this exact order — each
  ordering constraint was probed against a real database and fails the naive way:
  1. `RunPython` — through-table conversion: add `game_uuid`, `UPDATE … FROM games_game`,
     reconcile (zero unmatched), `SET CONSTRAINTS ALL IMMEDIATE`, `DROP COLUMN game_id`,
     rename, `SET NOT NULL`. **Must be first**: `DROP COLUMN games_game.id` fails while
     this FK exists. **`SET CONSTRAINTS` is not optional**: without it the next
     `ALTER TABLE` fails with `cannot ALTER TABLE … because it has pending trigger events`.
  2. `AlterField` ×6 setting `db_constraint=False`, keeping `to_field="uuid"` —
     `Purchase.related_game`, `Session.game`, `PlayEvent.game`, `GameStatusChange.game`,
     `Game.platform`, `Purchase.platform`. **Without this the migration dies** with
     `cannot drop constraint games_game_uuid_…_uniq … because other objects depend on it`.
  3. `RemoveField(game, "id")`, `RenameField(game, "uuid" → "id")`,
     `AlterField(game, "id", UUIDv7Field(primary_key=True, editable=False, serialize=False))`.
  4. The same three for `platform`.
  5. `AlterField` ×6 back to the final fields — `to_field` deleted, `db_constraint`
     default. Django recreates each constraint against the new pk under its own name.
  6. `RunPython` — restore the through table's FK, its `game_id` index, and the
     `(purchase_id, game_id)` unique index. `DROP COLUMN` cascaded all three away
     while Django's migration *state* still lists the `unique_together`, so
     `check-migrations` stays quiet and the guarantee is silently gone. Go through
     `schema_editor` (`_create_fk_sql`, `_create_index_sql`, `alter_unique_together`)
     so the names match Django's convention — ID-13 performs the mirror conversion and
     will look for exactly those names.

  The reverse gate lives on operation 6 (reverse runs last-to-first): restore the
  pre-promotion schema when `games_game` and `games_platform` are both empty, raise
  otherwise.

- [ ] **Step 3: Change the models.** `Game`/`Platform`: `uuid = UUIDv7Field(unique=True,
  editable=False)` becomes `id = UUIDv7Field(primary_key=True, editable=False)` —
  matching `UserLibrary`, which already has this shape. Delete `to_field="uuid"` from
  the four Game FKs and two Platform FKs; **keep** it on `Session.device` and
  `UserLibraryPreferences.default_device` (ID-14's). `to_field` becomes `fields.E312`
  the moment the field is renamed, so this is mandatory, not cleanup.

- [ ] **Step 4: Apply and verify against a real database.**
  `make migrate` then `make audit-uuid-identity`. Expect the audit to report exactly
  three stale inventory entries and nothing else. **Do not substitute `sqlmigrate`.**

- [ ] **Step 5: Shrink the inventory and rewrite the tripwire.**
  Remove `RESIDUAL_INTEGER_RELATIONS[("games_purchase_games", "game_id")]` and both
  `RESIDUAL_INTEGER_PRIMARY_KEYS` catalog entries from `games/identity_audit.py` — the
  audit asserts set *equality*, so a converted column left listed fails exactly as an
  unowned one does. **Rewrite** (do not delete)
  `tests/test_purchase_fk_uuid.py::test_the_purchase_games_through_table_is_still_integer_keyed`
  to pin the remaining half: `purchase_id` still integer, `game_id` now `uuid_v7` with
  an FK to `games_game(id)`. Deleting it leaves ID-13 with no warning.

- [ ] **Step 6: Flip the URLs.** The 8 catalog routes in `games/urls.py` become
  `<uuidv7:…>`; the converter is registered in `timetracker/urls.py` and until now
  unused. Narrow the view signatures widened in Task 1 to `UUID`. The three
  `game_id: int = 0` sentinels become `UUID | None = None` — a UUID is truthy and `0`
  is falsy, so `if game_id:` behaved, but the annotation was a lie. Fix the integer
  literals in `tests/test_deletion_helper.py` and `tests/test_returns.py`, which will
  otherwise `NoReverseMatch`.

- [ ] **Step 7: Flip the types.** `GameOption.value` and `PlatformOption.value` → `UUID`
  (leave `DeviceOption` integer — ID-14's). `partial_update_game(game_id: UUID)`,
  `PlayEventIn.game_id: UUID`, `GameOut.id: UUID`. `PlayEventRowProps.game_id` → `str`,
  then `make gen-element-types` to regenerate `ts/generated/props.ts` — the codegen'd
  reader is `Number(...)`, which yields `NaN` on a UUID and posts `null`.
  `SearchSelectOption["value"]` gains `UUID`.

- [ ] **Step 8: Flip the filters.** The four catalog `MultiCriterion` declarations and
  `PurchaseFilter.games` become `UUIDMultiCriterion`; delete `_games_to_q`'s
  `int(...)` coercion and its `FilterError("… must be integers")` — the criterion
  class now owns that guarantee. `stats_links`' two builders construct
  `UUIDMultiCriterion`. Leave `SessionFilter.device` on `MultiCriterion`.
  **The lookups themselves do not change**: Wave C already made every catalog lookup
  target-pk-relative, so they resolve UUIDs unaltered.

- [ ] **Step 9: Fix the remaining reads.** `OuterRef("uuid")` → `OuterRef("pk")` in
  `games/views/game.py:109` (the games list's *unconditional* `filtered_playtime`
  annotation — leaving it breaks every render, not just a filtered one) and
  `games/api.py:243,250`. `games/signals.py:116` `filter(uuid=)` → `filter(pk=)`.
  Drop three of the four `seed_related_initial` calls entirely; `games/forms.py:551`
  keeps only `"device"`.

- [ ] **Step 10: Fix the sample tooling.** In `load_sample_data`, flip the four catalog
  `FixtureRelationship(reference_field=…)` entries from `"uuid"` to `"pk"` (the two
  device entries stay), and move the platform remap on **both** sides: the value
  becomes `str(platform.pk)`, and the **key** must read the record's `pk` instead of
  `fields.get("uuid")`, which Step 11 deletes. Missing the key side leaves the map
  empty and raises `CommandError: Sample games.game references unknown Platform …`.
  In `anonymize_sample._anonymize`, collapse the now-redundant identity maps: drop
  `.only("pk", "uuid")`, `games_by_pk`, and `game_offsets_by_uuid`; `game_offsets`
  keyed by pk is the only map left, and `related_game_id` takes the chosen pk directly.

- [ ] **Step 11: Regenerate the fixture** with a throwaway transform script (not a
  database round trip — loading the old blob needs pre-cutover code while the
  migration needs post-cutover code). Per `games.game` / `games.platform` record:
  `pk` becomes the record's `fields.uuid`, and `fields.uuid` is deleted. Per purchase:
  each element of `games:` maps from the integer to that game's uuid. Foreign-key
  values are already uuids and must not change. Keep gzip `mtime=0` and no embedded
  filename so the blob stays a stable git object.

- [ ] **Step 12: Run the full gate.** `make check`. Expect green. If `e2e/` fails on
  stale assets, run `make ts` first — and never run e2e while `make dev` is up.

- [ ] **Step 13: Commit.**
  `git commit -m "feat: promote the catalog UUID identities to primary keys"`

## Task 4: Guarantees the cutover could silently lose

Each of these passes trivially if written carelessly. The notes are what make them
real tests.

**Files:** `tests/test_catalog_uuid_primary_key.py`, `tests/test_filters.py`,
`tests/test_api.py`.

- [ ] **Step 1: Uniqueness still *enforced*, not merely declared.** `Game`'s
  `unique_together` and its partial platformless-name `UniqueConstraint`. Insert the
  colliding row with `bulk_create` — `Model.save()` runs `clean()`, which dereferences
  the relation and raises in Python before PostgreSQL sees the row, so a `save()`-based
  test passes while proving nothing. A NULL never collides in a unique index, so the
  colliding row needs non-NULL values in **every** constrained column.
  `test_the_purchase_games_pair_is_still_unique` already exists and already drives the
  through model directly; confirm it still passes rather than rewriting it.

- [ ] **Step 2: Every `int`-typed endpoint, not just the search ones.** One case each
  for `/api/games/search`, `/api/platforms/search`, `/api/devices/search` (pinning the
  device endpoint's *integer* contract across the ID-11→ID-14 window),
  `PATCH /api/games/{id}/status`, the play-event create route, and a session read that
  exercises the nested `GameOut`.

- [ ] **Step 3: Server-built filter links survive serialization.** Render a game detail
  page and a stats page and assert 200. Both call `filter_to_json` with catalog ids as
  criterion values *and* as `labels` keys; a `UUID` reaching `json.dumps` is a 500.

- [ ] **Step 4: Stale filter values degrade, not crash.** A `?filter=` carrying an
  integer where a catalog UUID is now expected — the shape a pre-cutover saved preset
  or bookmarked URL has — renders 200 unfiltered with the "Ignored invalid filter"
  message, not a 500.

- [ ] **Step 5: Routes.** A catalog route resolves for a UUID and 404s for an integer.

- [ ] **Step 6: Run the full gate and commit.** `make check`, then
  `git commit -m "test: pin the guarantees the catalog promotion could silently lose"`
