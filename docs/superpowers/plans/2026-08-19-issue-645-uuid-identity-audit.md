# ID-10 (#645): UUID identity audit — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use `superpowers:subagent-driven-development`
> (recommended) or `superpowers:executing-plans`. Steps use checkbox syntax for tracking.

**Goal:** A read-only `audit_uuid_identity` command that proves the integer→UUID map is
complete and consistent, plus the anonymizer fix that makes its ordering check hold on
real fixture data.

**Architecture:** Pure computation in `games/identity_audit.py` (returns `Violation`
records, no I/O beyond a cursor), a thin management command that prints and exits
non-zero, following the `stats_data.py` / `stats_content.py` split already in this
codebase. Expectations are derived from Django model metadata and compared against
`pg_catalog`; only the *residual* integer set is pinned to a constant.

**Design spec:** [ID-10 design](../specs/2026-08-19-issue-645-uuid-identity-audit-design.md).
Governing plan: [wave plan](../specs/2026-08-17-uuid-identity-cutover-wave-plan.md), Wave D.

## Task 1: `uuid7_at` gains deterministic entropy

**Files:** modify `timetracker/uuidv7.py`; test `tests/test_uuidv7.py`.

**Produces:**

```python
def uuid7_at(
    moment: datetime, *, sequence: int | None = None, entropy: int | None = None
) -> uuid.UUID
```

`entropy` fills the 62-bit `rand_b` field; `None` keeps today's `secrets.randbits(62)`.
Out-of-range raises `ValueError`, mirroring the existing `sequence` guard.

- [ ] **Step 1** — failing tests in `tests/test_uuidv7.py`:
  - same `moment` + `sequence` + `entropy` twice → identical UUID;
  - a given `entropy` round-trips: `value.int & ((1 << 62) - 1) == entropy`;
  - `entropy=-1` and `entropy=1 << 62` each raise `ValueError`;
  - `entropy=None` (existing behaviour) still yields differing values across calls.
- [ ] **Step 2** — `make test ARGS="tests/test_uuidv7.py -k entropy"`. Expect failures
      (`unexpected keyword argument 'entropy'`).
- [ ] **Step 3** — implement. Keep the existing docstring's Method-1 note; extend it to
      say `entropy` exists so a caller with its own seeded RNG can be reproducible.
- [ ] **Step 4** — rerun; expect pass. Then `make test ARGS="tests/test_uuidv7.py"` to
      confirm nothing else moved.
- [ ] **Step 5** — commit: `feat: let uuid7_at take caller-supplied entropy`.

**Gotcha:** `secrets.randbits` must stay the default. Any caller switched to the `random`
module wholesale would make production UUIDs predictable.

## Task 2: audit core — introspection, type agreement, residual inventory

**Files:** create `games/identity_audit.py`; create
`games/management/commands/audit_uuid_identity.py`; create
`tests/test_uuid_identity_audit.py`; modify `Makefile`.

**Produces** (later tasks import these names verbatim):

```python
type TableColumn = tuple[str, str]      # ("games_purchase_games", "game_id")
type TableName = str                    # "games_game"
type OwnerLabel = str                   # "ID-11 (#646)"

class Violation(NamedTuple):
    check: str        # "type-agreement"
    subject: str      # "games_session.game_id"
    detail: str       # "Django expects uuid_v7, PostgreSQL has bigint"

class Note(NamedTuple):
    check: str        # "ordering"
    subject: str      # "games_userlibrarypreferences"
    detail: str       # "skipped: no ordering source field"

class CheckReport(NamedTuple):
    violations: list[Violation]
    notes: list[Note]

class RelationColumn(NamedTuple):
    table: TableName
    column: str
    target_table: TableName
    target_column: str
    expected_type: str

RESIDUAL_INTEGER_RELATIONS: dict[TableColumn, OwnerLabel]
RESIDUAL_INTEGER_PRIMARY_KEYS: dict[TableName, OwnerLabel]

def relation_columns() -> list[RelationColumn]
def actual_column_types(cursor) -> dict[TableColumn, str]
def check_type_agreement(relations, actual_types) -> CheckReport
def check_residual_inventory(relations, actual_types, primary_key_types) -> CheckReport
def primary_key_types(actual_types) -> dict[TableName, str]
```

Every check returns a `CheckReport`, not a bare violation list: check D has to report
"skipped" and "N NULL-source rows excluded" as first-class output, and the design makes
"skipped is never mistaken for passed" a requirement. Deciding this now avoids a
signature change in the middle of Task 3.

`relation_columns()` walks `apps.get_app_config("games").get_models(include_auto_created=True)`,
takes every `local_field` with `is_relation and field.column`, and reads
`field.target_field` for the target side and `field.db_type(connection)` for the expected
type. `actual_column_types` runs one `pg_catalog` query joining `pg_attribute` to
`pg_type` and reading **`pg_type.typname`**, which is the bare `uuid_v7` for domain
columns — the same string `UUIDv7Field.db_type` returns, so the two sides compare
directly.

Use `pg_type.typname`, **not** `format_type(a.atttypid, a.atttypmod)`. `format_type` is
search-path sensitive: a deployment whose `DATABASE_URL` carries
`options=-csearch_path=…` (those query parameters become psycopg `OPTIONS`, see
`timetracker/database.py:93-101`) makes it return `public.uuid_v7`, and check A would emit
15 false violations against exactly the long-lived production database the audit exists
to inspect.

## Task 3: identity health, ordering, referential agreement

**Files:** modify `games/identity_audit.py`,
`games/management/commands/audit_uuid_identity.py`, `tests/test_uuid_identity_audit.py`.

**Consumes:** `Violation`, `TableName`, `relation_columns()`, `actual_column_types()`.

**Produces:**

```python
IDENTITY_ORDER_SOURCE: dict[TableName, str]   # {"games_gamestatuschange": "timestamp"}
DEFAULT_ORDER_SOURCE = "created_at"

class IdentityModel(NamedTuple):
    model: type[Model]
    table: TableName
    identity_column: str    # "uuid", or "id" for games_userlibrary
    order_source: str | None

def identity_models() -> list[IdentityModel]
def check_identity_columns(cursor, identity_models) -> CheckReport
def check_ordering(identity_models) -> CheckReport
def check_referential_agreement(cursor, relations) -> CheckReport
```

`identity_models()` derives the list: a model qualifies if it has a local field named
`uuid` typed `uuid_v7`, **or** its pk is typed `uuid_v7`. That is eleven models — the
eight `uuid`-field carriers, `games_userlibrary` (uuid pk of its own), and
`games_userlibrarypreferences` + `games_purchaseconversionstate`, whose pk is the shared
`library_id`. The last two are what make check D's "skipped" branch reachable rather than
dead code. `order_source` is
`IDENTITY_ORDER_SOURCE.get(table, DEFAULT_ORDER_SOURCE)` when the model has that field,
otherwise `None`.

Check C, per identity model: column type is `uuid_v7`; `attnotnull` is true; a unique
index over exactly that column exists per `connection.introspection.get_constraints`;
`count(*) == count(DISTINCT identity)`; zero NULLs.

Check D, per identity model with an `order_source`: over rows whose source is non-NULL,
`order_by(identity)` pk sequence equals `order_by(order_source, "pk")` pk sequence.
Report the **first diverging pk pair**, not a boolean. Rows with a NULL source are
excluded and their count is reported. A model with `order_source is None`
(`games_userlibrarypreferences`, `games_purchaseconversionstate`) is reported as skipped,
never as passed.

Check E, per uuid-typed relation: a `LEFT JOIN` counts non-NULL values with no matching
target row, and `pg_constraint.convalidated` is true for that FK.

**Gotchas:**
- Migration `0006`'s `null_rows_sort_last` is **not** re-asserted. It was true only at
  migration time: a NULL-source row stamped with the migration clock stops sorting last
  the moment any newer row is inserted. Excluding NULL-source rows is the durable form.

## Task 4: anonymizer re-assigns uuids from anonymized timestamps

**Files:** modify `games/management/commands/anonymize_sample.py`,
`tests/test_anonymize_sample.py`.

**Consumes:** `uuid7_at(..., entropy=...)` from Task 1.

**Produces:** a `_reassign_uuids()` pass on `Command`, called at the end of `_anonymize`
(after every `created_at` rewrite, before `dumpdata`).

Scope: the **six dumped models** only — `Platform`, `Device`, `Game`, `Purchase`,
`Session`, `PlayEvent` (`DUMP_LABELS`, `anonymize_sample.py:36-44`). `GameStatusChange`
and `FilterPreset` carry a `uuid` but are never dumped, so reassigning theirs buys
nothing and costs a crash: `GameStatusChange.timestamp` is `null=True`
(`games/models.py:697`), and migration `0006:31-37` needed a fallback-clock branch for
exactly that. A production copy — the only kind of database this command runs against —
will have NULL timestamps, and `uuid7_at(None)` raises.

For each of the six, ordered by `(order_source, pk)` with the sequence restarting each
millisecond — migration `0005`'s `backfill_model_uuids` algorithm, with
`entropy=random.getrandbits(62)` for determinism. Then remap every referrer, updating the
child's FK attname through the old→new map. The `games:` many-to-many lists are integer
pks and stay untouched.

**Referrer discovery must use `model._meta.get_fields(include_hidden=True)`, not
`related_objects`.** `related_objects` filters out hidden relations, and
`UserLibraryPreferences.default_device` is declared `related_name="+"`
(`games/models.py:799-806`) — so `related_objects` silently omits the one `Device`
referrer outside the dumped set, leaving `games_userlibrarypreferences.default_device_id`
pointing at a pre-reassignment uuid. Remap **all** referrers including the two
non-reassigned models: `GameStatusChange.game` and `UserLibraryPreferences.default_device`
both need their FK values translated even though their own uuids stay put.

  - `test_uuid_timestamps_track_the_anonymized_created_at` — every `games.game` uuid in
    the output embeds `FIXED_EPOCH`; every `games.session` uuid embeds its own
    (offset) `created_at` to the millisecond.
  - `test_output_preserves_uuid_ordering` — per model, uuid order equals
    `(created_at, pk)` order in the emitted records.
  - `test_related_game_reference_follows_the_new_uuid` — the `related_game` value in the
    output matches the *new* uuid of the game it points at, not a stale one.
  - `test_hidden_device_referrer_follows_the_new_uuid` — a `UserLibraryPreferences` row
    with a `default_device` still resolves to a live `Device` after the pass. This is the
    `related_name="+"` trap; assert against the database inside the transaction, since
    the row is never dumped.
  - Existing `test_output_is_deterministic_for_a_fixed_seed` and
    `test_output_reloads_via_loaddata` must still pass unchanged.
- [ ] **Step 2** — `make test ARGS="tests/test_anonymize_sample.py"`. Expect the three new
      ones to fail.
- [ ] **Step 3** — implement `_reassign_uuids()`.
- [ ] **Step 4** — rerun the whole file. All eleven tests pass.
- [ ] **Step 5** — commit: `fix: derive sample uuids from the anonymized timestamps`.

**Gotchas:**
- The referrer remap must be **derived**, not a hand-list — a hand-list is exactly what
  ID-06 through ID-09 kept having to extend — but see the `include_hidden=True`
  requirement above. Add a test that `UserLibraryPreferences.default_device` is remapped;
  it is the one referrer a plausible-looking implementation misses, and nothing else in
  the suite would catch it.
- The new uuids are disjoint from the old ones (62 random bits), so a single multi-row
  `bulk_update` cannot trip the unique index mid-statement.
- FKs are `DEFERRABLE INITIALLY DEFERRED` and the transaction is rolled back, so updating
  a parent's `uuid` before its children is safe. Do **not** add
  `SET CONSTRAINTS ALL IMMEDIATE` here.
- Place the pass at the **end** of `_anonymize`, after every `created_at` rewrite. Nothing
  after it consumes the module RNG (`_load_overrides` and `_write_fixture` are
  deterministic), so it cannot perturb any other anonymized value — determinism rests only
  on `random.seed()` already having been called in `handle`.
- `uuid7_at`'s sequence is 12 bits. Every Game, Platform and Device collapses to the one
  `FIXED_EPOCH` millisecond — 851 games today, ceiling 4096. Let the `ValueError`
  propagate; do not silently wrap.
